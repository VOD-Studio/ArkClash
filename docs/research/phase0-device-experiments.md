# 阶段 0 真机实验记录

2026-11-12，设备 HBP-AL00（HarmonyOS 7.0.0.111，API 26），mihomo v1.19.33，Go 1.26.5。
实验代码在本分支（`test/vpn-phase0-experiments`），不合并到 `main`。

这些实验回答一个问题：未连接时内核放在哪个进程，以及 ADR-0001「界面退出或被杀都不影响代理」是否成立。

## 结论

1. **界面进程一死，系统就停 VPN。** 从最近任务清掉和被信号 9 强杀，结果相同。ADR-0001 的说法不成立。
2. **预热内核可行。** VPN 扩展进程可以只加载内核、不建隧道；这时没有隧道接口、状态栏没有 VPN 图标、系统没有登记 VPN。
3. **预热后点连接只要约 50 ms**，冷连接要约 5 s，而且冷连接有约 4.5 s 的断网窗口。
4. **两进程可以走沙箱内的 Unix 套接字通信**，不必开 TCP 端口。
5. **界面进程自己加载内核要多占约 120 MB**，不适合作为常规方案。

## 实验一：界面进程退出后 VPN 是否存活

| 情形 | 结果 |
|---|---|
| 界面切到后台 74 分钟 | 界面进程、VPN 进程、隧道都在 |
| 从最近任务清掉应用 | 系统以 `ClearSession` 杀界面进程，约 50 ms 后终止 `ClashVpnAbility`，隧道关闭，VPN 进程退出，40 s 内没有被拉起 |
| 已连接时界面进程被信号 9 杀死 | 约 300 ms 后系统终止 `ClashVpnAbility`，其余同上 |
| 待机时界面进程被信号 9 杀死 | 扩展进程 1 s 内被系统清掉 |

和官方《连接VPN》指南「服务生命周期」一节一致：调用 `startVpnExtensionAbility` 的应用进程退出时，系统主动停止 VPN。

## 实验二：扩展进程不建隧道（待机）

做法：`runtime.json` 带 `standby` 时，`onCreate` 里只加载内核和配置，不调用 `VpnConnection.create`。

| 观察项 | 待机 | 接入隧道后 |
|---|---|---|
| `vpn-tun` 接口 | 没有 | 有 |
| 状态栏 VPN 图标 | 没有 | 有 |
| 系统 `NetworkVpnManager` 登记 | 没有 | 调用 `SetUp` 时登记 |
| 扩展进程 | 存活 | 存活 |

没有测到的：

- 前台待机只观察了 2 分半，后台待机没有测。
- 设备上已信任过本应用，没有观察到首次授权弹窗的时机。
- 没有第二个 VPN 应用，待机时别的 VPN 能否正常启动没有测。

## 实验三：冷连接与预热后接入的耗时

「可用」指内核开始读隧道。各三次。

| 路径 | 点击到可用 | 构成 |
|---|---|---|
| 冷连接 | 5825 / 4870 / 5199 ms | 起进程约 140 ms，建隧道 31–64 ms，解析配置约 300 ms，应用配置 4.4–5.2 s |
| 预热后接入 | 66 / 50 / 48 ms | 建隧道 39–54 ms，把 fd 交给内核 1–3 ms |

- 待机本身从启动到内核就绪约 5.1–5.5 s，在用户点连接之前完成。
- 应用配置的 4–5 s 主要是初始健康检查（对节点逐个拨测），属于网络耗时。
- 冷连接时界面在约 660 ms 就拿到 controller 应答并显示已连接，系统路由约 200 ms 时已生效，内核约 5 s 后才开始读隧道。这段时间设备断网。这个问题在 `main` 上现在就存在。
- 预热后接入的端到端验证：浏览器访问被墙站点，内核日志里这条连接命中了代理节点。

## 实验四：进程间的本地套接字

内核（Go）在 VPN 扩展进程里监听 `filesDir/exp.sock`，界面进程用 ArkTS 的 `socket.LocalSocket` 连接。

- 监听和连接都成功，SELinux 没有拦截。
- 建连加一次往返共 17 ms。

## 实验五：界面进程加载内核的内存

界面进程动态 `import('libarkclash.so')`，以待机方式装好当前配置。PSS 由 `hidebug.getPss()` 取。

| 阶段 | PSS |
|---|---|
| 应用启动后的基线 | 63.6 MB |
| 加载动态库后 | 73.2 MB |
| 装好配置瞬间 | 246 MB |
| 10 s 后 | 185 MB |
| 60 s 后 | 184 MB |

净增约 120 MB。同一份配置在 VPN 扩展进程里，内核启动后 12 s 的 PSS 约 174 MB。
这些都是启动一分钟内的数字，不是长时间稳定后的值。

## 复现

```sh
make core && make hap MODE=debug && make install MODE=debug
hdc shell aa start -a EntryAbility -b com.vodstudio.arkclash --ps exp <动作>
hdc hilog | grep ArkClashExp
```

动作：`cold`（冷连接）、`standby`（待机）、`attach`（接入隧道）、`stop`、`sock`（套接字）、
`pss`、`vpnpss`、`loadcore`（界面进程加载内核）、`die`（界面进程自杀）。
