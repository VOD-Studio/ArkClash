# 0030 脚本与附加规则组合、仪表盘运行状态

- 状态：已采纳，待真机验收

## 背景

FlClash v0.9.4 允许同一份配置同时使用脚本和附加规则。一个命名出口可以被多条规则引用，由各配置分别选择实际出站。仪表盘也提供一个入口查看内核、版本更新和资源下载。

## 决定

- 保留现有脚本绑定和附加规则文件。内核先执行已选脚本，再解析附加规则的出站，按配置级、启用的全局、脚本输出的原有规则顺序应用。旧脚本绑定继续有效，旧附加规则按同一顺序参与合并。
- 新规则用可选 `customExit` 区分命名出口和内置策略。每份配置在 `added-rules.json` 保存出口映射。映射目标可用时优先使用，其次尝试同名出站、配置的 MATCH 出站和 DIRECT。历史 `MATCH-TARGET` 继续校验实际出站，错误时保留运行配置。
- 手动应用同时核对脚本标识和配置级规则修订。脚本库同步和保存只应用脚本变更，保留运行中的规则修订。选择脚本生成的出站时，按需向 VPN 进程请求预览，响应只包含名称和类型。
- 仪表盘使用已有的内核状态和 Geo WebSocket。Geo 下载任务每秒至多推送一次中途进度，开始和结束时立即推送。切页或后台退订，Geo 下载任务由 VPN 进程继续管理。缺少 Geo 设置时默认每 24 小时更新，仍由现有调度器判断资源是否到期。已保存的开关和周期随升级保留。
- UI 进程在首次前台显示后异步检查应用更新，每次运行最多自动检查一次。手动检查共用同一状态，用户可在常规设置关闭自动检查。
- GitHub 分发构建从官方 Release 获取文件名、大小和 SHA-256。用户选择下载后由系统传输服务写沙箱缓存，校验成功后才能用文件选择器保存。发布的未签名包需用户签名，维护者调试签名包仅适用于登记过的设备。应用市场分发构建使用 AppGallery Kit 检查并打开系统更新界面，由应用市场完成安装。

## 后果

Geo 下载增加少量按需推送。规则映射使用已解析的配置数据，应用失败时保留原配置和已打开的 TUN。真机验收在同一设备上核对运行状态抽屉、脚本生成出口的规则命中、热应用与冷加载，以及更新下载的进度、取消、校验和保存。应用市场安装验收需要同签名的在架新版本。性能门禁记录冷启动到首个可操作控件、8 小时待机电量、新连接时延和 24 小时内核重启次数。
