# 0036 在 VPN 进程响应系统内存压力

## 状态

已采纳。

## 背景

HBP-AL00（API 26）上保留了 VPN 进程的 7 条 `SwapFull` 和 2 条 `LowMemoryKill` 退出记录。两类原因都涉及整机内存压力。进程被终止后，系统 TUN 随之消失。缓存连接意图和重新启动扩展的约束见 [ADR-0017](0017-core-ready-without-vpn.md)。

## 决定

VPN 扩展在自己的进程中订阅 `ApplicationContext` 的环境事件。收到前台或后台的低内存、严重低内存通知时，通过 NAPI 工作线程调用 Go 的 `debug.FreeOSMemory()`，执行垃圾回收并向系统归还空闲堆页。扩展销毁时注销监听。

启动时解析配置、加载规则集和预取其他配置会留下临时对象。扩展在已有的一次性预取任务收尾时主动回收一次，覆盖系统冻结进程后无法投递通知的情况。空配置库跳过。预取在内核就绪 10 秒后才开始，首页渲染和首次连接均可独立进行。

扩展合并尚在处理中的通知。内核回收结束后留出 10 秒间隔，避免系统短时间内重复通知引发多次全堆扫描。仅隐藏界面或中等压力时沿用 Go 的常规回收节奏。配置大小、规则集和并发连接数都影响活跃堆大小，目前缺少给所有用户设置同一堆上限的数据。

## 后果

回收期间保留活动连接、配置及 TUN。GC 消耗 CPU，收益取决于当时可以归还的空闲页。系统冻结进程后可能无法送达通知，整机持续缺少内存时仍可终止 VPN。

## 真机验证

使用同一台 HBP-AL00、同一组配置和 ARM64 Release 包，将 `3429f1e` 与修复版依次覆盖安装。每次冷启动后从首页连接 VPN，在系统浏览器打开 Google，让 ArkClash 退到后台。以 `hidumper --mem <vpnPID>` 的 Total PSS 取样，同时核对 PID 和系统 TUN。在启动后第 38 秒采样，再用 `aa send-memory-level -p <vpnPID> -l 2` 定向发送严重内存压力通知。

冷启动耗时取设备端发起 `aa start` 至首页 `dashboard_interactive` 标记的时间差。新 HTTPS 连接经内核当前规则请求 Google 的 `generate_204`，每次禁用连接复用，统计收到响应头的延迟。这两组测量分别取 5 次和 10 次，公网延迟受网络波动影响。

| 2026-11-26 同机测量 | 原版 0.6.2 | 修复版 |
|---|---:|---:|
| 启动后 14 秒，VPN 进程 PSS | 131.1 MiB | 130.7 MiB |
| 启动后 21 秒，VPN 进程 PSS | 132.2 MiB | 107.7 MiB |
| 启动后 38 秒，发送通知前 PSS | 132.2 MiB | 111.8 MiB |
| 压力通知后约 2 秒，VPN 进程 PSS | 132.2 MiB | 106.5 MiB |
| 冷启动到可操作，中位数 / P95 | 745 / 773 ms | 756 / 795 ms |
| 新 HTTPS 连接到响应头，中位数 / P95 | 358.5 / 1203 ms | 306.5 / 416 ms |

修复版启动后 15.5 秒记录了一次预热收尾回收，严重压力通知触发了第二次回收。两次回收前后 VPN 进程一致，TUN 持续存在。系统浏览器访问 Google 的连接经 TUN 命中代理节点，两组 HTTPS 请求均为 10/10 返回 204。

修复版退后台后，设备从 11:12:10 到 11:15:10 息屏，结束时系统仍处于 SLEEP。唤醒前后 VPN PID 相同，TUN 保持连接。唤醒后新建 HTTPS 连接，379 ms 收到 204。系统退出记录未新增。

两组冷启动均超过 500 ms 目标。8 小时待机耗电需在同机同网络、不充电的条件下锁屏对照，24 小时稳定性需核对 VPN 的 PID、bootId 与退出记录。本次短时实验未覆盖这两项和同类客户端对照。

## 后台掉线后取证

掉线后连接手机，在仓库根目录运行 `make vpn-exits`。它按 VPN 进程名向系统查询最近保留的最多 50 条退出记录，包括设备时间、前后台状态、原因和记录 ID。掉线当时可以不接电脑。用 `make -s vpn-exits > ~/arkclash-vpn-exits.log` 可保存结果，多台设备时用 `HDC_TARGET` 选择手机。

2026-11-26 下午在同一台 HBP-AL00 上复现。15:11:09 确认 ArkClash 已退到后台，系统隧道仍在，VPN 进程 PSS 为 138.0 MiB，`oom_score_adj` 为 500，界面进程为 300。15:11:23 隧道仍在。15:11:34 系统给 VPN 进程记了一条 `SwapFull`，15:11:38 采样时只剩界面进程，隧道已消失。设备当时保留的 17 条 VPN 进程退出记录全部发生在后台，其中 14 条 `SwapFull`、3 条 `LowMemoryKill`。定位具体内存分配还需要进程退出前的堆数据。[华为应用终止原因说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/appkilled-guidelines/)

回到 ArkClash 后，新 VPN 进程完成预热。点击首页连接后隧道重新建立，系统浏览器请求 Google Public DNS 返回 HTTP 200。
