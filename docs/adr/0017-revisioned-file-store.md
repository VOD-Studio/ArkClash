# 0017 配置文件使用带版本的事务清单

- 状态：目标决策，待实现与文件锁真机验证（2026-11-13）
- 实现后替代：[0009](0009-arkclash-commands-on-controller.md) 中交接瞬间“最后写入生效”的规则。

## 背景

多配置、节点选择、脚本、共享节点池、关联规则和备份恢复涉及多份文件。单文件临时写再rename不能保证内容、用量、链接和当前配置属于同一版本；后台更新和UI编辑竞争时最后写赢会覆盖用户修改。

继续沿用文件模型是减少现有数据迁移面的选择，不依据未经证明的“鸿蒙数据库不支持多进程”。代价是必须显式实现并测试文件事务。

## 决定

逻辑记录经 `Store.snapshot/commit` 访问；业务不直接覆盖JSON。数据内容是不可变blob，单个`state/manifest.json`记录schemaVersion、revision与各逻辑记录的引用，manifest原子替换是唯一提交点。

UI和VPN共用小型`libarkstore.so`提供异步原生文件锁与文件操作，不链接Go/mihomo；UI依旧不加载内核。锁可用性和进程中止后的释放必须在真机验证，不能用时限到期强抢仍存活的写入者。

提交合同：

1. 下载、压缩、脚本和大文件写入在锁外准备到独立staging。
2. 短事务异步持锁，重读manifest并比较expectedRevision。冲突返回CONFLICT，不覆盖；可重放操作最多重读重试3次。
3. 内容校验、fsync与rename先完成，manifest最后提交并同步目录。拒绝路径逃逸和symlink。文件系统耐久性以实测为准，不将rename夸大为已验证断电一致性。
4. 锁内不发网络、不等待Go或NAPI回调。丢失进程后从完整manifest恢复；孤儿blob有保留期和引用检查，再清理。
5. settings、当前配置、选择、扩展关联与恢复均走同一提交点。Go运行资源与UI缓存分目录，不将流量历史落盘。

跨文件状态与内核运行态的协调见0014的applyJournal；两者不是一个天然原子事务。备份读取固定revision，恢复准备与校验后一次提交；设备授权、socket、令牌、运行意图不备份。

## 后果

- 授权前和宿主在线时都能安全保存，后台完成无需UI回调落盘。
- 删除/重命名的关联完整性、备份快照、磁盘满与进程中止可以从同一接口测试。
- 新增一个不含核心的原生库和崩溃恢复协议；实现必须验证其成本，不把JSON文件当作无需测试的简易数据库。
