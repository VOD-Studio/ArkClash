# ADR-0019：诊断采集跟随应用，实时列表跟随页面

## 状态

已采纳，取代 [ADR-0016](0016-visible-diagnostics.md) 的采集生命周期和历史快照边界。运行身份校验、动作事务、事件背压和 WebSocket 控制帧约束延续。

## 背景

FlClash v0.9.3 在[应用级 CoreManager](https://github.com/chen08209/FlClash/blob/be84736605527034689c95bf27828ff27d912c5e/lib/manager/core_manager.dart#L155-L173) 接收连接和 DNS 事件，不依赖这两个页面是否打开。Android 的 [Flutter 事件监听解绑](https://github.com/chen08209/FlClash/blob/be84736605527034689c95bf27828ff27d912c5e/android/app/src/main/kotlin/com/follow/clash/plugins/ServicePlugin.kt#L50-L86) 后，即使 VPN 服务继续转发，也不会补录。原先离开 ArkClash 工具页再复查时，短连接和已完成查询都已错过。

## 决定

- UI 的应用级接收端确认核心就绪后，以 `expectedBootId` 连接已认证 controller 的 `/arkclash/diagnostics/capture`。这个 WebSocket 只维持采集，不传记录、不发周期数据；内核接受后只回一条 `ready`。页面切换和应用后台保留它；接收端退出、核心完全停止或 boot 变化时关闭。不加轮询、保活或后台运行权限。
- VPN 进程内的连接观察 hook 在纳入跟踪时记录建立，关闭时记录累计流量；DNS hook 在解析完成时记录结果，时间仍为解析开始时间。连接保持全部活跃状态与最近 2,000 条历史，DNS 保持最近 3,000 条；记录不上磁盘、不进日志。只有采集通道或相应页面流存活时才记录，不回放采集关闭期间的流量。
- 工具页继续只在可见、应用在前台且核心就绪时订阅各自的数据 WebSocket。打开或恢复时读取同 boot/配置的完整有界 `snapshot`，包括未打开页面期间的记录；`reset` 同样是完整快照。活动连接基线不会伪装成新建立记录。独立的暂停滚动视图仍有上限，不受正常历史窗口替换影响。
- 无人查看连接时不运行秒级流量采样；关闭事件读取当时的计数，重新打开时读取活跃连接当下的计数。无人查看 DNS 时只写环形缓冲区，不安排发送。可见流仍合并至多每秒一帧；容量淘汰按采集器累计，背压合并按数据会话计数，两者不混用。
- 普通断开 VPN 不重置仍就绪的同代次历史。成功热切换退休旧配置的两条数据流与历史，在恢复入口前启用新代次采集；应用级采集连接仍属同一个 boot。解析失败不退休旧会话。完全停止或换 boot 同时清除采集连接和历史；不会跨代次合并。

## 后果

应用后台、两个诊断页关闭时，不做列表刷新、WebSocket 记录编码和传输或秒级流量采样。每次连接建立/关闭、DNS 解析完成仍增加一次内存记录操作；这不是持久访问日志，环形容量和系统终止进程均会使记录不可恢复。未做真机耗电、冷启动、连接延迟及长期稳定性测量；分别用同机同配置锁屏 8 小时、可操作首帧耗时、新连接延迟分布和 24 小时 boot 变化作改动前后对照。
