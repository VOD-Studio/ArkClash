# 0028 标准覆写的规则顺序与应用时机

覆写顺序及命名出口由 [ADR-0030](0030-composed-overrides-and-live-status.md) 更新。

- 状态：已采纳，待真机验收

## 背景

FlClash v0.9.3 的标准覆写允许按配置添加规则、停用特定的全局规则并指定 MATCH 目标。ArkClash 已有有序全局规则与脚本模式。参见 [#80](https://github.com/VOD-Studio/ArkClash/issues/80)。

## 决定

- 将每份配置的规则、停用的全局规则 ID 和 MATCH 目标与全局规则保存在同一份 `added-rules.json`。沿用版本核对及原子提交。删除全局规则时一并清理停用关系。旧文件按各配置没有附加规则、启用所有全局规则读取。
- 规则顺序为配置级附加规则、启用的全局规则、原配置规则。两层附加规则的 `MATCH-TARGET` 优先取配置设置，否则取原配置最后一条 `MATCH`。仍无法解析时拒绝候选配置并显示错误。脚本模式和自定义配置使用各自的规则生成流程。
- 运行时保留当前应用的配置级规则及修订。配置级编辑提交后，在覆写页通过既有的应用命令核对 boot、配置及修订后热应用，或在下次加载该配置时生效。全局规则或规则集修改只有影响当前已应用的规则时才重建。

## 验收

宿主用合成配置核对规则匹配顺序、缺失 MATCH、切换与应用时机。手机上用同一组配置验证连接和切换期间的代理命中及应用耗时，同时按项目门禁对比冷启动、新连接延迟、8 小时待机耗电和 24 小时内核重启次数。
