# 0014 为 x86_64 模拟器单独适配 Go 工具链

- 状态：已采纳（2026-11-16）。原生加载、构建和签名应用启动通过，VPN 转发待验收。
- 跟踪：[#99](https://github.com/VOD-Studio/ArkClash/issues/99)

## 背景

Linux x86_64 的 HarmonyOS API 26 模拟器只能运行对应 ABI 的原生库。原来的内核和 NAPI 桥只编译 ARM64，不能靠修改 HAP 元数据运行。Go 1.26.5 的 linux/amd64 共享库同样使用 initial-exec TLS，不能由 musl 安全地动态加载；共享库入口还假定初始化函数能收到 argc/argv。问题来源见 [golang/go#54805](https://github.com/golang/go/issues/54805)。

0002 的 ARM64 补丁处理 `load_g`/`save_g`，而 amd64 的 TLS 访问由编译器/汇编器生成，不能直接复用该补丁。此次扩展 0002，不改变 UI 与 VPN 的进程边界。

## 决定

- `ABI` 只接受 `arm64-v8a`、`x86_64`，默认仍是 ARM64。各架构分别缓存私有 Go 工具链和补丁依赖，Go 版本由 `.go-version` 选择。
- ARM64 保持原补丁。x86_64 使用 `scripts/go-ohos-amd64.patch`，同时重建私有工具链里的 `asm`、`compile`、`link`，不修改系统 Go 或模块缓存。
- 在 linux/amd64 共享模式下，将 `MOVQ TLS, reg` 降为对应的原生辅助函数调用。辅助函数通过 ELF TLSDESC 解析 C 定义的线程局部 `g`，返回相对线程指针的偏移，后续 FS 访问不变。
- 每个辅助函数只修改目标寄存器；保存标志位和临时寄存器，并对齐解析调用的栈。TLSDESC 本身可能修改标志位，不能直接把一次解析调用当成原来的 MOV。偏移解析及紧随其后的 TLS 读取/写入都标记为不可异步抢占，防止迁移线程后复用旧偏移。
- 共享库初始化传入空的 argv/envp/auxv 终止表，auxv 继续由运行时读取 `/proc/self/auxv`。与 ARM64 一样，配置从启动 JSON 传入，不依赖库内环境变量。
- 不采用固定 TCB 槽位、`LD_PRELOAD` 或预先链接内核的启动程序；应用仍在 VPN 进程动态加载真实内核。
- Hvigor 的 native `abiFilters` 选择 NAPI 桥架构，native library filter 同时排除非选中 ABI 的预编译库。ARM64 文件名不变；x86_64 HAP 在模式后带 `-x86_64`，两架构的 dist 产物共存。Hvigor 的中间目录共享，不支持并发打包不同 ABI。

## 验证与边界

`make core` 分别构建两种 ABI，并检查没有 ARM64 `TLS_TPREL` 或 x86_64 `TPOFF/GOTTPOFF` 重定位。两种 HAP 已分别打包并检查原生库 ELF machine：ARM64 为 183，x86_64 为 62，包内没有混入另一架构。

`make core-smoke ABI=x86_64 HDC_TARGET=127.0.0.1:10026` 在 API 26 模拟器的临时目录里用 `RTLD_NOW` 动态加载真实 `libclash.so`。它验证版本返回、停止状态、非法启动参数被拒绝，以及加载前 4 个已有线程和加载后 16 个新线程上的 C→Go→C 调用与内存释放。一次运行完成 5,250 轮、42,002 次 API 调用，耗时 28.081ms；这是 shell 冒烟时长，不是应用冷启动或连接延迟。

脚本只访问本次创建的临时目录并在退出时删除，不读取其他应用日志；库不执行 `dlclose`。该检查不启动 VPN/TUN，不能替代签名后应用内启停、代理转发、网络切换与长时间稳定性验证。

2026-11-24 在独立的 HarmonyOS 7（API 26）x86_64 模拟器执行 `make run ABI=x86_64`，安装并启动已签名的 0.6.0 调试包，检查配置导入、自定义配置、工具、进阶配置和主题页面，主题可切换到深色。本次验证覆盖界面和装机流程。

## 后果

- 升级 Go 时，需要重新检查 x86 汇编器的 TLS 指令展开、寄存器与标志位保存、抢占标记、native TLS 解析约定，不能仅以补丁能应用作为通过标准。
- 默认 ARM64 不增加 x86 的辅助调用；x86 的 TLS 调用开销尚未做应用级基准。
- 设备验收仍需同机同配置对照：冷启动到可操作时间；同网络和屏幕状态下开代理待机 8 小时耗电；受控目标的新连接延迟分布；连续 24 小时运行的内核 bootId 与转发状态。当前没有这些数字，模拟器冒烟不作为性能达标证据。
