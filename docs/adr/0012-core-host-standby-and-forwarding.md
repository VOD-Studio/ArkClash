# 0012 内核在 VPN 扩展中预热，启动意图与实际转发分开

- 状态：目标决策，待实施及平台门禁验证（2026-11-13）
- 修正：[0001](0001-core-in-vpn-extension.md) 的「界面进程被杀不影响代理」结论；共享库与进程隔离决定保留。
- 详细协议和验收以第一阶段架构 Issue 为准，入口见本目录 README。

## 背景

FlClash 在用户启动代理前已经加载配置，因此可以列出 provider 节点、选择节点、延迟测试和预览配置。ArkClash 0.4.x 只在建立 VPN 后加载核心，无法提供相同的未连接交互。

阶段 0 实验保存在远端分支 `test/vpn-phase0-experiments`，提交 `1f12341` 的 `docs/research/phase0-device-experiments.md`。HBP-AL00 / HarmonyOS 7.0.0.111 上观察到：

| 项目 | 观测及边界 |
|---|---|
| 清最近任务或 UI 进程 SIGKILL | 系统随后终止 VPN 扩展；已连接强杀实验约 300 ms，观察期内未恢复。SIGKILL 不等于真实内存回收实验 |
| 无 TUN 加载核心 | 成功，无隧道接口和 VPN 图标；未验证是否占唯一 VPN 服务名额 |
| 冷核心到开始处理 TUN | 4870 / 5199 / 5825 ms；`/version` 约 0.66 s 即可响应，因此不能作为转发就绪判据 |
| 已预热后接入 | 48 / 50 / 66 ms；不是首个 HTTPS 成功的端到端耗时 |
| UI 加载并初始化核心 | 稳态 PSS 相比基线净增约 120 MB；不能直接推算回收概率 |

后台待机等待按用户要求跳过，不能写成已通过。首次授权、无 TUN 后台存活、其它 VPN 共存、反复拆建 TUN 和宿主自停都还需验证。实验报告中与这些边界冲突的早期概括，以本记录的限定为准。

## 决定

UI 不加载 `libclash.so`。核心仍只在 VPN 扩展运行；前台在可启动宿主时加载配置，**配置就绪后才创建系统 TUN**。待机时关闭业务入站监听，但保留配置与按需测试能力。

运行状态分四个维度：

- 宿主：off / starting / online / stopping / failed。
- 配置：empty / loading / ready / failed。
- 用户意图与会话模式：stopped / started，tun / proxyOnly。
- 实际转发：stopped / starting / running / pausing / paused / stopping / failed。

按需 SSID 暂停保留用户启动意图和计时，关闭入站和 TUN；离开后恢复。本阶段暂停原因只定义 excludedSSID；主动停止、系统撤权或另一 VPN 接管清空意图，之后的网络事件不自动恢复。仅代理模式打开入站但不建 TUN，后台可行性由平台门禁验证。不能把 ready、running 和已连接合成一个布尔值。

连接、停止、重连和配置提交由一个协调器串行改变状态，昂贵准备工作在锁外执行。操作带 generation，停止使旧操作过期，晚到 fd 必须清理。fd 交接、listener 的关闭责任和系统 destroy 顺序在实现票里固定并真机验证，不凭猜测双重 close。

首次需要核心能力时清楚说明授权用途；拒绝后保留编辑草稿和缓存摘要，但不把摘要当完整校验、provider 列表或预览。保存的授权历史不是系统权限的真值。其它 VPN 共存不通过时不得以无图标掩盖冲突。

前后台只做必要的事件订阅；后台仍有用户启动意图时保留宿主所需的通知、网络事件和调度。无启动意图时释放宿主，不引入未经验证的定时保活。UI 死亡会终止 VPN，产品必须明确这一边界；通知异常退出不能假设销毁回调总能执行。

## 后果

- 缓存首帧与核心加载分离；完整节点能力可在未转发时提供，但依赖宿主权限与平台门禁。
- UI 后台退订、释放列表，降低内存占用；独立进程不能承诺不受 UI 回收影响。
- 冷连接避免在数秒配置准备阶段提前接管路由；实际端到端收益仍须按测量规程采样。
- 24 小时稳定性、8 小时待机、其它 VPN 共存、仅代理后台、授权拒绝与撤销必须有独立真机结果；未通过前不能宣布完整功能交付。
