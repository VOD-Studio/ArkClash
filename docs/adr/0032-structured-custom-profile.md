# 0032 自定义配置的结构化编辑

## 状态

已采纳。

## 背景

现有配置存储、导出、备份和热切换都以 mihomo YAML 为输入。自定义配置还需要在手机上直接操作代理组、成员、拨号链和整份路由规则。

## 决定

- 自定义配置仍用配置库已有的 `custom` 类型和 YAML 文件。结构化编辑只改动相关 YAML 节点，保留未编辑的内容。URL 和文件导入先解析为草稿，用户保存后才替换配置。
- 结构解析、序列化和依赖环检查在 TaskPool 运行。保存使用原有候选文件、内容修订检查和运行配置热切换事务。代理组改名时，在同一份 YAML 中同步组成员、匹配规则、拨号、DNS 和 NTP 引用。
- 从节点库选中的节点以定义副本进入配置。导入的代理集合和规则集沿用 YAML 中的定义。

## 后果

- YAML 编辑和结构化编辑使用同一份内容，导出和备份可直接携带自定义配置。
- 节点库中的后续修改不会同步到已复制的节点。跨配置的共享资源引用和改名传播需要独立的持久化模型及构建步骤。
- 结构检查区分循环、格式错误和缺失引用。正在运行的配置仍须通过内核热切换才会落盘。
- 宿主状态未确认时，新配置可以存入配置库，沿用当前选择和运行状态。
