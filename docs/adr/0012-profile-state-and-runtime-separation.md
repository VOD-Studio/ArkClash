# 0012 配置持久状态与实际运行状态分离

- 状态：已采纳；0.5.0 本地实现，真机门禁待统一验收。

## 背景

普通配置管理需要保留用户下一次想使用的目标，即使热切换失败，也必须准确显示仍在转发的旧配置。代理页面允许断开时预选节点，并要求同名分组在不同配置之间互不影响。

mihomo v1.19.33 的 `executor.ApplyConfig` 会在 `updateProfile` 中按全局组名缓存恢复选择。若先恢复 ArkClash 的每配置选择而保留 `profile.store-selected`，之后的 `patchSelectGroup` 会将它覆盖。界面在启动后补发选择又会留下使用错误出站的窗口。

## 决定

- `profiles/list.json.current` 保存用户目标；controller 的 `profile` 保存实际运行配置。先保存新目标，再有条件地请求热切换；失败时保留旧运行配置和明确错误。
- 每配置节点选择以 `profiles/<id>.selected.json` 为唯一持久来源。离线由 UI 在存储短锁内原子写入，在线由 Go 选择事务切换、保存；写失败时恢复原转发目标。
- `applyOverrides` 强制关闭 mihomo 全局 `profile.store-selected`，不删除已有缓存。启动及热切换在应用配置和启用转发之前恢复相应配置的选择。
- `bootId` 区分核心实例，`configRevision` 只随完整配置提交前进。选择命令携带这两项前置条件和 `operationId`，旧配置请求拒绝，幂等重放不重复关闭连接。
- 写入资格使用宿主三态：`running` 走核心事务，确认 `stopped` 才能由界面写业务文件，`unknown` 只读缓存并保留草稿。转发未就绪或 controller 失联不等于停止；配置更新器和节点选择的最终提交也必须守住该资格。
- 代理图使用核心实例范围内的不透明节点 ID，并单独提供每组实际采用的成员 ID。显示名不能充当唯一身份；同组、不同 provider 的同名成员也分别显示和测速，过期实例拒绝。
- provider 更新后的当前成员与实际采用分开记录。URLTest 缓存仍引用旧实例时，图保留该实例摘要及 `retired` 标记，直到核心实际切换；退休实例不能重新选择或发起测速，界面不能把仍在转发的出站显示为空。
- 现有 mihomo 首选接口按 `Set(name)` 指定，无法精确区分同组的同名实例。此类成员保留实际采用标记及测速，界面明确禁止有歧义的单独指定；已有名称首选仍可在组上清除，不静默改写用户节点名。
- 保持现有 controller 与沙箱文件两条通道。完整 CORE_BUILD/CORE_STORE 架构仍按新规格另行验收，本记录不宣称该目标已完成。

## 后果

- 热切换失败后，目标与运行标签可以不同；界面必须同时说明，不能把目标标签当成实际已切换。
- 同名分组不会串用另一配置的节点选择，转发开始前即可应用离线预选。
- 订阅中的 `profile.store-selected` 不再决定节点选择存储；其他 mihomo 缓存不因此清除。
- 该决定补充 [0010](0010-hot-switch-reload-in-vpn.md) 的目标选择和节点恢复规则，其余热切换约束保持。已备宿主回归覆盖全局旧缓存与当前配置冲突；真实代理链路和快速重连仍需真机验证。
