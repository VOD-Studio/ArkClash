# 0039 按内核代次持续采集日志与结构化脱敏展示

## 状态

已采纳。更新 [ADR-0029](0029-general-settings-and-log-capture.md) 中的日志采集生命周期与日志记录格式。

## 背景

ADR-0029 将日志观察器绑定在日志页订阅期间，离开页面或热切换配置即清空缓冲。这导致只有停留在日志页才能看到记录，断线或切配置后无法回溯。同时，原有脱敏策略将所有连接和 DNS 日志折叠为不含目标、规则与节点的泛化句子，且把 sing/gVisor 等组件通过动态字符串发出的调试日志统一归为「未分类内核事件」，难以排查真实问题。

## 决定

- **按内核 boot 持续采集**：开启「日志捕获」后，内核在启动完成或保存常规设置时立即注册日志观察器，将最近 5,000 条记录保存在内核内存环形缓冲中，不落盘。离开日志页、应用进入后台或热切换配置均不停止采集、不清空缓冲；关闭「日志捕获」或内核完全停止时释放观察器与缓冲。
- **按 boot 订阅与显式清空**：`/arkclash/diagnostics/logs` 只校验 `expectedBootId`（不再绑定 `configRevision`），页面可见时订阅实时帧，不可见时退订以节省界面电量，重新打开时从当前 boot 的环形快照恢复完整历史。新增 `POST /arkclash/diagnostics/logs/clear`（带 `expectedBootId`），允许用户清空内核日志缓冲并向在线页面推送空 `reset`。
- **结构化字段与安全脱敏**：
  - 连接路由、拨号失败与 DNS 日志按 mihomo 固定模板（对齐 FlClash v0.9.3）拆出 `tag`、`target`、`source`、`rule`、`proxy`、`reason` 和 `detail` 等可选字段，便于界面分层排版和按关键字检索；来源中的进程与 UID 仍不输出。
  - 拨号错误正文与组件动态日志（sing-tun、gVisor、WireGuard 等）保留诊断语义，但统一脱敏 URL、凭据/令牌、`private_key`/`preshared_key`、WireGuard IPC 配置正文、`lookup` 上游域名以及裸 IPv4/IPv6 地址；DNS 上游保留公开协议与主机名并剥离凭据、查询参数与私有路径。
- **界面重构**：日志页对齐连接页与 DNS 页的 `ScrollDestination` + `ScrollControls` 交互，顶部提供搜索、多选等级筛选和更多菜单（切换内核日志等级、开关日志捕获、清空、导出），卡片按 24 小时制和结构化层级展示，向上滚动自动暂停并以底部悬浮胶囊回到最新。

## 后果

- 开启日志捕获后，即使日志页未打开，每条满足当前日志等级的内核日志仍会写入内存环形缓冲（无页面订阅时不编码 JSON、不发 WebSocket 帧，默认仍为关闭状态且默认日志等级为 `error`）。
- 5,000 条上限之外的旧记录和进程被系统回收后的内存记录仍无法恢复。
- 冷启动、8 小时待机耗电、新连接延迟和 24 小时稳定性需在真机开启与关闭日志捕获前后分别对照测量。
