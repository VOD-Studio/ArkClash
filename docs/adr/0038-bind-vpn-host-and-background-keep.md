# 0038 绑定 VPN 扩展与后台保持连接

## 状态

已采纳。补充 [ADR-0037](0037-resume-after-vpn-reclaim.md)：宿主被回收后的恢复从「回到前台」提前到「绑定断开」。

## 背景

[ADR-0036](0036-vpn-memory-pressure.md) 记录的退出原因全部是后台的 `SwapFull` 和 `LowMemoryKill`。OpenHarmony memmgr（`reclaim_priority_manager.cpp`）按进程计算回收优先级：

- 长时任务只给申请它的进程（`GetCreatorPid()`）置 `isBackgroundRunning`，该进程降到 200。
- 扩展进程取「绑定方中最好的优先级 + 100」与自身状态的较小值；没有绑定方时是 500。
- 开源默认配置在可用内存低于 500 MB 时查杀 400 及以上的进程，低于 400 MB 查杀 300 及以上。

VPN 扩展因此处在第一档查杀范围，先于普通后台应用（400）被回收。鸿蒙官方文档和 API 26 SDK 均没有让 VPN 扩展常驻或提升优先级的接口；长时任务只能由 UIAbility 申请，文档原文是「一个UIAbility申请长时任务后，整个应用下的所有进程均不会被挂起」，管的是挂起，不是查杀。

同类客户端的做法：ClashBox 在界面进程挂模拟画中画、模拟定位、模拟下载或 `taskKeeping` 长时任务，界面每秒检查内核 socket，断了就重新拉起扩展；另有把内核和 TUN 放进界面进程的「前台模式」。Clash Mate、Paws、TunBox 在界面进程申请 `dataTransfer` 长时任务并用隧道流量更新实况窗。

## 真机实验

2026-11-26，HBP-AL00（API 26），ARM64 Release 包，临时实验代码不提交。`oom_score_adj` 读自 `/proc/<pid>/oom_score_adj`。

| 条件 | 界面进程 | VPN 进程 |
|---|---:|---:|
| 原版，界面前台 | 0 | 500 |
| 原版，界面后台 | 300 | 500 |
| 界面持有 `dataTransfer` 长时任务，后台 | 200 | 500 |
| 界面绑定 VPN 扩展，前台 | 0 | 100 |
| 界面绑定，后台 | 300 | 400 |
| 界面绑定，后台约 3 分钟后 | 380 | 480 |
| 界面绑定并持有长时任务，后台 | 200 | 300 |

- `VpnExtensionAbility` 的类型声明没有 `onConnect`，但系统会调用它。扩展不返回 `RemoteObject` 时，`connectServiceExtensionAbility` 立即回调 `onDisconnect`，优先级不变；返回空的 `rpc.RemoteObject` 后绑定成立。
- 扩展未运行时绑定会让系统拉起扩展，`onCreate` 收到的 Want 就是绑定的 Want。
- 宿主进程退出后约 40–70 ms，界面收到 `onDisconnect`。
- 界面进程主动退出后 VPN 进程和 TUN 都保留。OpenHarmony 文档「调用 startVpnExtensionAbility 的应用进程退出时停止 VPN」在这台设备上不成立。
- 界面持有长时任务时，可以在后台调用 `startVpnExtensionAbility` 重新拉起扩展并接通 TUN。

## 决定

**绑定（默认开启）**：VPN 扩展的 `onConnect` 返回空 `RemoteObject`，不承载业务调用，业务仍走 controller（[ADR-0003](0003-ui-core-via-external-controller.md)）。界面在认证状态确认宿主运行后，按 `bootId` 绑定一次，绑定失败不重试同一宿主。完整停止扩展前先解绑。绑定 Want 携带 `arkclashHostBinding`：宿主恰好退出时系统会借绑定拉起扩展，扩展据此直接停止，不写实例和停止回执。

**绑定断开即宿主退出**：用户希望保持连接、且没有停止回执（系统设置断开、其他 VPN 接管都会留下回执）时恢复连接，流程沿用启动和连接的单飞与代次保护。30 分钟内最多恢复 4 次，间隔依次为 2 秒、15 秒、1 分钟、5 分钟，之后等用户回到前台（[ADR-0037](0037-resume-after-vpn-reclaim.md)）。界面在前台时总是立即恢复；在后台时界面会被挂起，只有后台保持开启才恢复。

**后台保持连接（默认关闭）**：在「网络」设置页开启。连接期间界面进程申请 `dataTransfer` 长时任务，界面降到 200，绑定的 VPN 进程随之降到 300。实况窗每 5 分钟用 `vpn-tun` 的累计收发字节更新一次进度，满足「10 分钟内更新进度」的要求。开启时要求允许通知，否则实况窗发不出去，任务会被系统取消。

- 用户移除通知后不再申请，下次连接时恢复；系统取消或申请失败时，回到前台再申请一次。设置页显示被系统暂停、停止和通知被移除等状态。
- 刚收到严重内存压力时推迟 30 秒恢复，避免新宿主约 190 MiB 的启动峰值（[ADR-0036](0036-vpn-memory-pressure.md)）再次触发回收。
- 该偏好不进备份：它依赖当前设备的通知授权。

**不采用**：
- 模拟定位和静音音频：API 26 新增 `SYSTEM_SUSPEND_POSITION_NOT_MOVED` 和 `SYSTEM_SUSPEND_AUDIO_PLAYBACK_MUTE`，锁屏静置正是这两种情形；音频还会让设备无法进入深度休眠。
- `taskKeeping`：手机需要 ACL 权限 `KEEP_BACKGROUND_RUNNING_SYSTEM`。
- 模拟画中画：文档限定视频播放、通话和会议场景，桌面会常驻小窗。
- 内核和 TUN 放进界面进程：违背「UI 进程不加载 `libclash.so`」，依赖把 UIAbility 的 context 强转为 VpnExtensionContext 这一未写入文档的行为。
- 每秒检查宿主：绑定断开已经是推送信号。

## 后果

- 绑定使 VPN 进程在界面后台时从 500 降到 400–480，与普通后台应用同档，不再最先被回收；没有耗电和通知代价。
- 后台保持把 VPN 进程降到 300，并把掉线时长从「直到用户回到应用」缩短到约 9 秒。代价是常驻通知、界面进程不再被挂起，以及每 5 分钟一次的通知更新。8 小时待机耗电尚未测量，开启前后需同机对比。
- 空闲时隧道流量低，系统可能以 `SYSTEM_SUSPEND_DATA_TRANSFER_LOW_SPEED` 暂停任务；暂停期间界面被挂起，后台恢复失效，退回 ADR-0037 的回前台恢复。锁屏静置 24 分钟未出现暂停，更长时间仍待观察。
- 绑定是第三条跨进程连接，但不传数据；进程间的业务通道仍只有 controller 和文件。

## 真机验证

2026-11-26，同一台 HBP-AL00，ARM64 Release 包。宿主被回收由临时构建模拟：界面经绑定通道通知 VPN 进程直接退出，不走清理，不留回执。

| 场景 | 结果 |
|---|---|
| 仅绑定，界面后台 | VPN 进程 400，约 3 分钟后 480 |
| 开启后台保持，界面后台 3.5 分钟 | 界面 200、VPN 进程 300，稳定不变 |
| 开启后台保持，锁屏静置 24 分钟，每 2 分钟采样 | 界面 200、VPN 进程 300，TUN 一直存在，长时任务未被暂停或取消 |
| 开启后台保持，界面后台时宿主退出 | 40 ms 后收到断开，2 秒后开始恢复，8.9 秒后确认 TUN，新宿主重新绑定，回到 300 |
| 恢复后系统浏览器打开 Google 搜索 | 8 秒内 72 条连接走代理规则，0 条直连，0 条失败 |
| 扩展未运行时绑定 | 系统拉起扩展，扩展记 `created by host binding, stopping` 后随即退出 |

冷启动、8 小时待机耗电、24 小时稳定性和新连接延迟本次没有测量。恢复不进入首帧路径，也不增加轮询或常驻任务（后台保持关闭时）。
