# 0031 原子恢复配置库与 WebDAV 备份

议题 [#85](https://github.com/VOD-Studio/ArkClash/issues/85) 描述的独立 Store 尚未进入本分支。备份保留现有配置与资源模型，并采用一个明确的提交点切换配置库。应用继续使用 mihomo 控制器与沙箱完成跨进程通信。

- `libarkstore.so` 是独立的异步 NAPI 入口。首次备份操作才加载 ZIP、SHA-256 和离线 WebDAV 实现，界面进程不加载 `libclash.so`。
- `.profile-storage.lock` 位于配置库外。ArkTS 文件锁和 Go flock 共用同一文件。配置下载的临时文件与任务锁留在 `profile-work/`，运行态、Geo 数据库和其他缓存留在库外。
- 快照依据实体清单在锁下为源内容建立硬链接。写者以原子重命名替换源文件，因此后续压缩使用同一份快照。模拟器的应用沙箱拒绝硬链接时，会在持锁期间复制源文件。快照释放后才等待文件选择、压缩或 WebDAV。
- ZIP 带产品标识、格式与数据版本、快照标识和 SHA-256 清单。解压到独立暂存目录，核对名称、大小、哈希和业务引用，再按 ID 合并或覆盖。缓存与系统 VPN 状态无需归档。配置摘要与管理规则集的编译产物从源内容重新生成。
- 恢复提交前，在短锁下比对快照引用。遇到并发修改重新计算并重新确认删除。Linux `RENAME_EXCHANGE` 一次切换完整的 `profiles/`，随后清理旧目录。旧版根目录中的规则、DNS、常规、Geo 和仪表盘设置由新库接管，首次恢复前仍按旧位置读写。
- 已提交的 ArkData 界面设置使用归档中的偏好清单补写，完成后记录该清单的版本。运行态应用单独返回结果，失败保留已恢复的数据和重试入口。在应用读入当前库之前，旧内核代次的设置写入会被拒绝。
- WebDAV 使用固定应用子目录和手动备份。在线转发经内核按当前规则拨号，已就绪但未转发时直连，内核离线由独立库直连。认证支持 Basic 和 MD5 Digest，跨源重定向移除认证头。归档包含敏感数据，导出时显示 ZIP 未加密提示。

API 26 x86_64 模拟器使用独立应用数据和合成配置验证。经系统选择器保存并读取 ZIP，经本机 WebDAV 服务上传和下载。仅配置合并保留两份配置和原当前项，取消覆盖保持两份，确认后只保留备份中的一份。全部数据恢复可还原备份保存的策略。宿主用例另验证同 ID 配置恢复保持 TUN，运行配置修订仅递增一次。
