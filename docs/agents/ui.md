# 界面约束（ArkUI）

## 动效

- 页面切换、分组展开、卡片增删和编辑态应有连续过渡，节奏对照用户录屏；优先使用鸿蒙原生 Tabs、Swiper、Sheet、属性动画与弹簧曲线，不以瞬间替换或只转箭头代替内容过渡。
- 缩放、位移用于表达按下反馈、编辑操作或空间关系，不给无关状态添加装饰性动画。展开收起按真实内容尺寸布局，相邻项跟随移动，支持中途反向。
- 动画 API 先查官方知识 MCP，再核对本机 SDK 声明；Skill 速查与声明冲突时，以当前官方文档和 SDK 为准。不用 ArkTS 逐帧回调模拟系统可承担的动画，页面不可见时停止持续动效。
- `@Monitor` 中不调用 `flushUIUpdates` 或 `flushUpdates`（会抛 140002）；用户异步保存完成后再开启动画事务。`applySync` 嵌套时内层闭包会被跳过，也不能用它机械替换监听回调里的刷新。
- 退出编辑或停止持续动效时，用零时长动画修改同一组属性来终止旧无限动画；完成回调必须核对组件挂载状态和动画代次，不能覆盖反向操作的新状态。
- 自定义 `HdsTabs` 构造参数使用 `index` 配合 `onChange`，不能照搬原生属性双向绑定语法；原生 `Swiper.index($$...)` 按 SDK 使用，不混为同一限制。
- 仅在原生列表的 `onAppear` 后访问对应 Scroller；`onDisAppear` 先清绑定状态。滚动偏移从有效滚动事件记录，卸载与过期回调不再查询 Scroller，不用零时延定时器猜测布局就绪。注意原生属性 `onDisAppear` 与 Sheet 选项 `onDisappear` 的拼写不同。
- 包装可交互子控件的容器不使用 `HitTestMode.Block`，它会阻断子节点；工具层用 `Default` 保留子按钮并隔离下层兄弟节点。ArkUI `ClickEvent` 没有 Web 的 `stopPropagation`，不要照搬事件 API。
- `MenuItem` 不接受子组件，子菜单通过 `builder` 传入；Symbol 使用 `symbolStartIcon`，不传给仅支持图片的 `startIcon`。配置卡长按菜单打开期间不执行卡片选择点击。
- 系统开启"减弱动态"时，所有非必要动效都停掉。
- 动效验收必须观察真机中间帧、快速反向和结束状态，不能用编译通过或终态截图代替。

## 视觉

- 页面结构、字号、间距和圆角以固定 FlClash v0.9.3 及其 Prism UI 源码为准：手机仪表盘外卡 34vp、内部区块 22vp，通用界面采用对应的 AppCorner 参数，不统一压成 16vp。
- 表面层级和阴影按对应组件还原；浮动栏、顶部和底部模糊、API 26 沉浸光感保留原生实现，不借平台风格改变内容排列和操作入口。底部浮动栏的原有图标、布局、材质和交互都属于保留项。
- 普通操作图标使用鸿蒙原生 Symbol，不复制 FlClash 图标；服务品牌标志保留真实产品图形与原始配色。
- 出站模式保留原有 `CapsuleSegmentButtonV2` 沉浸光感切换组件，不替换成三枚自绘按钮。
- 首页验收覆盖每张卡片和每个抽屉的真实布局与交互；编译通过不代表界面通过。
- 界面只保留必要状态、真实错误和可执行操作，不常驻开发说明、数据口径长文或重复的“未判定”。不能为了简洁把未检测或连通结果伪装成解锁成功。
- 异步 IP 及类型、质量使用与最终内容等尺寸的骨架占位；统计尚未实现时明确显示开发中，不拿当前连接分类代替连接、请求和 DNS 的目标统计。
- 首页配置卡在首页打开原生详情抽屉，不切到配置页；编辑和导入复用现有表单及脏数据保护，不改变配置页结构。
- 代理列表展开后保持连续的分组外层与内嵌节点；折叠以内容实际高度驱动后续分组布局，不用固定占位加手工位移补偿。页面顶部“代理”标题栏保留列表从其后穿过的沉浸滚动和模糊效果，不裁掉整张列表；分组吸顶标题与页面标题栏是两个不同层级，遮挡只处理该分组标题背后的节点及圆角漏出。
- 颜色从资源文件（`resources/base/element/color.json` 和 `dark/`）引用，深浅色都要能用。

## 性能

UI 是"打开快、不耗电"这两个指标的主要承担者（见 AGENTS.md「产品底线」）。

- 首帧只依赖本地缓存（preferences、上次的快照），网络和内核数据在首帧之后到达。
- 长列表（代理组、节点、连接、日志、规则）用 `LazyForEach` 加 `@Reusable` 组件，按需渲染。
- 高频数据（流量速率、连接数）合并后再刷新，最多每秒刷新一次界面；页面进入后台就退订内核推送。
- 状态尽量拆细，只让真正变化的组件重绘。`build()` 里只描述界面，计算放在状态更新的地方。

## 操作反馈

- 保存、切换、更新、测速等操作结果使用原生 Toast，不向列表或卡片插入临时提示条，不因此改变内容高度或滚动位置；同次结果只提示一次，页面不可见时不打断用户。
- 进行中的反馈放在已有按钮或状态位，不为“正在更新”“部分测速失败”等消息新增布局。
- 禁止 Alert 类弹窗。多项动作选择使用原生底部 ActionSheet；需要异步执行和进度反馈的确认使用原生底部 Sheet，保留取消、返回和脏数据保护。
- 真正的运行状态、表单错误和批量失败明细不能被伪装或吞掉；操作提示也不能冒充已经应用成功的业务状态。
